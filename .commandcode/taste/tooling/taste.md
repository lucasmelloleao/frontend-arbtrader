- Maintains a multi-host AI agent setup (Claude Code, Command Code, Codex, Cursor) in the same repo and expects agent configuration to stay in parity across hosts — when a new host is added, its config should incorporate the content from the canonical source (skills, slash commands, hooks, docs) rather than minimal stubs ("incorpore" = full incorporation). - Prefers agent enforcement logic centralized once in host-agnostic shared scripts (e.g., `tooling/agent-hooks/`) with per-host config files pointing at them, and wants new host surfaces added to the enforcement gates/tests and CODEOWNERS so changes can't silently disable the setup. Confidence: 0.6

Confidence: 0.8
- Runs the production build locally (`bun run build`) as the decisive validation for build/prerender changes after `bun run verify` is green — tests passing is not sufficient proof the Vercel build will succeed, so the full Next 16 production build must complete with all routes prerendered (or intentionally Partial-Prerendered) before redeploying. Confidence: 0.6
- Has no admin rights on their machine — tooling installs and setup must work in user scope (user-level binaries, PATH via user environment variable) without elevation. Confidence: 0.9
- Develops on Windows and expects repo tooling/scripts to be cross-platform: no dependence on Unix-only binaries (e.g., `grep`) and explicit handling of path separator differences (e.g., `Bun.Glob` returning `\` on Windows). Confidence: 0.7
